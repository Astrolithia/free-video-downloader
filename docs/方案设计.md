# FreeVidGrab 方案设计文档

## 1. 整体架构

FreeVidGrab 采用**前后端分离构建、一体化部署**的架构：前端使用 Vue 3 + Vite + Tailwind CSS 构建 SPA，生产时由 FastAPI 托管构建产物；开发时 Vite Dev Server 通过代理转发 API 请求到 FastAPI。前后端通过 HTTP API 和 SSE 通信。

```
┌────────────────────────────────────────────────────┐
│                    Browser (前端)                    │
│  Vue 3 + Tailwind CSS + TypeScript (Vite 构建)     │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────┐  │
│  │ URL 输入  │→ │ 解析展示  │→ │ 下载 + 进度监听   │  │
│  └──────────┘  └──────────┘  └──────────────────┘  │
└────────────────────┬───────────────────────────────┘
                     │ HTTP / SSE
┌────────────────────▼───────────────────────────────┐
│                  FastAPI (后端)                      │
│  ┌───────────┐  ┌───────────────────────┐          │
│  │  API 路由  │  │ SPA 托管              │          │
│  │ /api/*    │  │ frontend/dist/ 产物   │          │
│  └─────┬─────┘  └───────────────────────┘          │
│        │                                            │
│  ┌─────▼──────────────────────────────────────┐    │

│  │  │ video_service │  │ douyin (抖音专用)  │   │    │

│  │  └──────────────┘  └───────────────────┘   │    │
│  └────────────────────────────────────────────┘    │
```

## 2. 技术选型

| 层级 | 技术 | 选型理由 |
| --- | --- | --- |
| **Web 框架** | FastAPI | 原生异步支持、自动 OpenAPI 文档、Pydantic 数据校验、性能优异 |
| **ASGI 服务器** | uvicorn | FastAPI 官方推荐，支持热重载、HTTP/1.1 |
| **视频引擎** | yt-dlp | 社区活跃、覆盖 1000+ 平台、持续更新 |
| **HTTP 客户端** | httpx | 支持异步/同步、流式下载、跟随重定向 |
| **前端框架** | Vue 3 (Composition API) + Tailwind CSS v4 | 组件化开发、响应式状态管理、TypeScript 类型安全 |
| **前端构建** | Vite | Vue 官方推荐，极速 HMR，开发体验优异 |
| **实时通信** | Server-Sent Events (SSE) | 单向推送场景最简方案，浏览器原生支持 |
| **音视频处理** | ffmpeg | 业界标准，yt-dlp 自动调用合并音视频流 |

## 4. 核心模块设计

### 4.1 API 层

API 层负责接收前端请求、参数校验和响应格式化，不包含业务逻辑。所有路由挂载在 `/api` 前缀下。

#### 接口列表

| 方法 | 路径 | 功能 | 请求体/参数 | 响应 |
| --- | --- | --- | --- | --- |
| POST | `/api/parse` | 解析视频元信息 | `{ url: string }` | 视频标题、缩略图、时长、格式列表 |
| GET | `/api/thumb` | 代理缩略图 | `?url=<encoded_url>` | 图片二进制流 |
| POST | `/api/download` | 发起下载任务 | `{ url, format_id?, audio_id? }` | `{ task_id }` |
| GET | `/api/progress/{task_id}` | 下载进度推送 | 路径参数 task_id | SSE 事件流 |
| GET | `/api/file/{task_id}` | 获取下载文件 | 路径参数 task_id | 文件流（application/octet-stream） |

#### 请求模型（Pydantic）

```python
class ParseRequest(BaseModel):
    url: str

class DownloadRequest(BaseModel):
    url: str
    format_id: str | None = None
    audio_id: str | None = None
```

### 4.2 服务层 — video_service

video_service 是系统的核心模块，负责：

1. **URL 提取**：从用户输入（可能包含分享文案）中提取有效的 HTTP(S) 链接
2. **视频信息提取**：调用 yt-dlp 获取视频元数据，简化格式列表
3. **下载任务管理**：基于内存字典的轻量级任务存储
4. **进度广播**：通过发布-订阅模式向多个 SSE 连接推送进度
5. **文件清理**：定期删除过期文件

#### 任务状态机

```
┌─────────┐    start_download    ┌──────────────┐
│ pending  │ ──────────────────→ │ downloading  │
└─────────┘                      └──────┬───────┘
                                        │
                                        ▼
                                 ┌──────────────┐
                                 │   merging    │ (音视频合并)
                                 └──────┬───────┘
                                        │
                              ┌─────────┴─────────┐
                              ▼                   ▼
                       ┌──────────┐        ┌──────────┐
                       │   done   │        │  error   │
                       └──────────┘        └──────────┘
```

#### DownloadTask 数据结构

```python
@dataclass
class DownloadTask:
    task_id: str           # 12 位随机 hex
    url: str               # 原始 URL
    title: str             # 视频标题
    status: str            # pending | downloading | merging | done | error
    percent: float         # 0.0 ~ 100.0
    speed: str             # 下载速度（如 "2.5MiB/s"）
    eta: str               # 预计剩余时间
    filename: str          # 下载完成后的文件路径
    error: str             # 错误信息
    _listeners: list       # SSE 订阅者队列列表
```

#### 进度广播机制

采用发布-订阅模式，每个 SSE 连接对应一个 `asyncio.Queue`：

- `subscribe()`：创建新的 Queue 并加入监听列表
- `emit(event)`：向所有 Queue 推送事件
- `unsubscribe(queue)`：连接断开时移除 Queue

这种设计支持同一任务的多个客户端同时监听进度。

#### 格式简化逻辑

yt-dlp 返回的原始格式列表包含大量冗余条目。`_simplify_formats()` 的处理策略：

1. 遍历所有格式，找到码率最高的纯音频流（`best_audio_id`）
2. 过滤掉无视频流的条目
3. 按 `{label}-{ext}` 去重
4. 按分辨率从高到低排序
5. 每个格式附带 `best_audio_id`，供前端请求合并下载

### 4.3 服务层 — douyin（抖音专用模块）

抖音平台的视频无法通过标准 yt-dlp 流程可靠获取，因此设计了独立的解析和下载模块。

#### 设计思路

- **无 Cookie 方案**：使用移动端分享页（`iesdouyin.com`）获取视频数据
- **数据来源**：页面中的 `window._ROUTER_DATA` JSON 包含完整的视频元信息和播放地址
- **URL 缓存**：模块级字典缓存已解析的下载地址，避免重复请求

#### 处理流程

```
用户链接 → 短链解析（v.douyin.com → 跟随重定向）
         → 提取视频 ID（/video/(\d+)）
         → 请求移动端分享页（iesdouyin.com/share/video/{id}/）
         → 正则提取 window._ROUTER_DATA
         → JSON 解析 → 获取播放地址（play_addr.uri）
         → 构造 1080p 下载链接
         → httpx 流式下载
```

#### 关键实现

- **短链解析**：通过 httpx 跟随重定向获取最终 URL
- **User-Agent 伪装**：使用 Android 移动端 UA
- **同步/异步双模式**：`extract_info()` 为异步（用于解析），`download_sync()` 为同步（在线程池中执行）

### 4.4 前端（Vue 3 SPA）

前端使用 **Vue 3 Composition API** + **TypeScript** + **Tailwind CSS v4** 构建，通过 **Vite** 进行开发和打包。

#### 组件结构

| 组件 | 职责 |
| --- | --- |
| `App.vue` | 根组件，组合所有子组件，管理全局状态 |
| `NavBar.vue` | 顶部导航栏（品牌标识、锚点链接） |
| `HeroSection.vue` | 主标题 + URL 输入框 + 解析按钮 + 错误提示 |
| `VideoResult.vue` | 解析结果卡片（缩略图、标题、格式选择、下载按钮） |
| `FormatPill.vue` | 单个清晰度选项按钮 |
| `DownloadProgress.vue` | 下载进度面板（进度条、状态文字、保存按钮） |
| `FeatureGrid.vue` | 功能特色展示（静态） |
| `PlatformList.vue` | 支持平台列表（静态） |

#### Composables（可复用逻辑）

**`useVideoParser`** — 封装视频解析逻辑：

- `parseVideo(url)` — 调用 `POST /api/parse`，结果写入 reactive `videoInfo`
- `isParsing` — 加载状态 ref
- `parseError` — 错误信息 ref
- `debouncedParse(url)` — 300ms 防抖自动解析

**`useDownloader`** — 封装下载与 SSE 进度监听：

- `startDownload(url, formatId, audioId)` — 调用 `POST /api/download` 并启动 EventSource
- `progress` — reactive 对象（status, percent, speed, eta, error, taskId）
- 自动管理 EventSource 生命周期，组件卸载时关闭连接

#### 交互流程

```
粘贴链接 → [300ms 防抖] → 自动触发解析
                          ↓
                    POST /api/parse
                          ↓
              渲染 VideoResult 组件
              （v-for FormatPill，自动选中最高画质）
                          ↓
                  用户点击"下载"
                          ↓
                   POST /api/download
                          ↓
              EventSource 监听进度
              DownloadProgress 组件响应式更新
                          ↓
              完成 → 显示"保存文件"按钮
              失败 → 显示错误提示
```

#### 进度监听（SSE）

使用浏览器原生 `EventSource` API 接收后端推送，在 `useDownloader` composable 中统一管理：

- `downloading`：更新进度条百分比、速度、剩余时间
- `merging`：进度条满格，提示"正在合并音视频"
- `done`：显示下载完成，提供文件保存链接
- `error`：显示错误信息
- `heartbeat`：忽略，仅用于保活连接

#### 开发与构建

- **开发模式**：`npm run dev` 启动 Vite Dev Server（端口 5173），`/api` 请求代理到 FastAPI（端口 8000）
- **生产构建**：`npm run build` 输出到 `frontend/dist/`，由 FastAPI 的 SPA fallback 路由托管

```
前端                        后端 API                    Service 层
  │                           │                            │
```

```
  │ ────────────────────────→ │                            │
  │                           │  start_download()          │
```

## 6. 并发与异步设计

### 6.1 异步架构

- FastAPI 的异步路由处理 HTTP 请求
- yt-dlp 和抖音下载操作为 **CPU/IO 密集型同步代码**，通过 `loop.run_in_executor(None, func)` 放入默认线程池执行，不阻塞事件循环
- SSE 进度推送使用 `asyncio.Queue` + `asyncio.wait_for` 实现非阻塞等待

### 6.2 任务管理

- 所有下载任务存储在内存字典 `_tasks: dict[str, DownloadTask]`
- 任务 ID 为 12 位随机 hex（`uuid.uuid4().hex[:12]`）
- 任务在以下情况被清除：
  - 手动调用 `cleanup_task(task_id)`
  - 定期清理：文件修改时间超过 10 分钟

### 6.3 生命周期管理

使用 FastAPI 的 `lifespan` 上下文管理器：

- **启动时**：创建后台清理任务（`asyncio.create_task`）
- **关闭时**：取消清理任务（`task.cancel()`）

## 7. 部署方案

### 7.1 本地开发

```bash
# 安装后端依赖
pip install -r requirements.txt

# 安装前端依赖
cd frontend && npm install && cd ..

# 确保 ffmpeg 已安装
ffmpeg -version

# 启动后端（端口 8000）
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

# 启动前端开发服务器（端口 5173，API 自动代理到 8000）
cd frontend && npm run dev
```

> 开发时访问 `http://localhost:5173`（Vite HMR），生产时构建后访问 `http://localhost:8000`。

### 7.2 生产部署建议

| 方面 | 建议 |
| --- | --- |
| **进程管理** | 使用 Gunicorn + UvicornWorker 多进程部署 |
| **反向代理** | Nginx / Caddy 做前端反代，处理 HTTPS 和静态文件 |
| **CORS** | 收紧 `allow_origins` 为实际域名 |
| **存储** | `downloads/` 可挂载为独立卷或 tmpfs |
| **容器化** | 提供 Dockerfile，基于 `python:3.12-slim`，安装 ffmpeg |
| **监控** | 接入日志收集和错误监控（如 Sentry） |

### 7.3 容器化参考

```dockerfile
FROM node:22-slim AS frontend
WORKDIR /frontend
COPY frontend/package*.json ./
RUN npm ci
COPY frontend/ .
RUN npm run build

FROM python:3.12-slim
RUN apt-get update && apt-get install -y ffmpeg && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app/ ./app/
COPY --from=frontend /frontend/dist ./frontend/dist/
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## 8. 后续演进方向

| 方向 | 说明 |
| --- | --- |
| **持久化存储** | 将任务状态从内存字典迁移至 Redis/SQLite，支持服务重启后任务恢复 |
| **用户认证** | 增加简单的登录机制，限制匿名访问频率 |
| **队列调度** | 引入 Celery/RQ 等任务队列，控制并发下载数量 |
| **播放列表支持** | 支持批量解析和下载播放列表 |
| **更多平台适配** | 针对其他难以通过 yt-dlp 处理的平台增加专用模块 |
| **WebSocket 替代 SSE** | 双向通信，支持取消下载等操作 |
| **前端路由** | 引入 Vue Router，支持多页面（如下载历史、设置页） |
